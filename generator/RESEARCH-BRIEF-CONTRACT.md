# RESEARCH BRIEF CONTRACT — v2

The handoff file between **Marcus** (Research Agent) and **Seraphina** (Sales Page Agent).

**Rule:** Marcus writes this file. Seraphina reads this file. Nothing else passes between them.
If a field is missing, Seraphina uses the documented fallback and flags it in the gaps report.

**File location:** `C:\Users\Owner\oc-site\generator\briefs\{slug}.json`

> ⚠️ **Do NOT write briefs to `~/VIP-Lead-Machine/`.** That repo runs an automatic
> "vault backup" process that deletes untracked files. It is why all work moved to
> `oc-site`. Briefs written there will silently disappear.

**Naming:** lowercase, hyphenated, matching the published URL path.
- City brief → `irvine.json` → publishes to `/irvine/`
- Community brief → `irvine-orchard-hills.json` → publishes to `/irvine/orchard-hills/`

## WHAT CHANGED FROM v1 (read this before using)

| # | Change | Why |
|---|---|---|
| 1 | Added `identity.page_type` (`city` \| `community`) | v1 had no way to express a city page. Drives required fields, template, and link direction. |
| 2 | Publish target is the **static generator**, not WordPress | The live pages are generated by `generate.js` → GitHub Pages. Seraphina writes data, not HTML. |
| 3 | Pricing formula defined explicitly | v1's `sqft × rate` produced impossible numbers (4,200 sqft × $3.25 = $13.6K, but range claimed $34K high). |
| 4 | Added `market.market_rate_range` + honesty rule | Live pages claim "$4.75/sqft is the Irvine average." Market data says $2.74–$4.89. That's the ceiling, not the average. |
| 5 | Added `layout.module_order` + global uniqueness registry | The generator enforces a unique section order per page. Marcus must assign it; nothing in v1 did. |
| 6 | Added `local_pack` block (Apify Google Maps) | v1 tracked organic competitors only. The 3-pack is ranked by GBP signals, which v1 captured nowhere. |
| 7 | Expanded `media` for `VideoObject` schema | A bare YouTube embed earns no rich result. Schema needs title, description, duration, upload date, thumbnail. |
| 8 | Client story **registry** — one real story, one page, forever | v1's example put "Douglas & Sheri" in Rancho Cucamonga; they're Pelican Hill clients on the live OC page. |
| 9 | Interlinking moved to a **post-publish reconciliation step** | Linking is a graph problem. A per-brief `internal_links` array can't make the city page link down to communities published later. |
| 10 | `"complimentary"` replaces `"free"` in **all** customer-facing copy | Locked brand standard. |

## FIELD RULES FOR MARCUS

### Required — never ship without these

**All pages:** `identity.*` (except `community` on city pages), `layout.module_order`,
`market.home_value_low/high`, `market.market_rate_range`, `architecture.primary_style`,
`architecture.typical_paintable_sqft`, `geography.streets` (min 2), `geography.landmarks` (min 1),
`geography.geo`, `palette.colors` (all 4 roles), `pricing.cost_answer_sentence`,
`seo.*` including `answer_capsule` and `viz_intro`, `faqs` (min 6)

**City pages additionally:** `identity.child_urls`, `local_pack.*`
**Community pages additionally:** `identity.community`, `identity.parent_url`

### Optional — Seraphina has fallbacks

- `media.*` → placeholder frames; hero falls back to the static poster hero
- `story.*` → if `is_real_client: false`, the representative template is used and labeled as such
- `local_pack` on community pages → inherits from the parent city brief

### Never invent

- **Street names** — verified on Google Maps or omitted
- **HOA rules** — found on the association's own site or set `hoa_has_color_guidelines: null`
- **Client names or stories** — see the Client Story Registry below
- **Review quotes** — real Google reviews only, never generated
- **Home values, income, sqft** — from a cited source in `meta.sources`, never estimated silently
- **Review counts or ratings for VIP** — must match the live Google Business Profile exactly

## THE THREE REGISTRIES

Global state that no single brief owns. Marcus reads and updates all three.

### 1. Client Story Registry — `generator/registry/client-stories.json`

A real client story is used on **exactly one page, ever**.

```json
{
  "douglas-and-sheri": { "used_on": "/orange-county-sales-page/", "city": "Newport Beach", "community": "Pelican Hill", "verified": true },
  "ceasar-and-julie":  { "used_on": "/orange-county-sales-page/", "city": "Irvine", "community": "Shady Canyon", "verified": true }
}
```

Before assigning a story, Marcus checks this file. If the story is taken, or no real client
exists for that page, set `is_real_client: false` and Seraphina renders the representative
template with a visible "Representative project" label. **Never** move a real client to a
different city than the one they actually live in.

### 2. Module Order Registry — `generator/registry/module-orders.json`

The generator fails the build if two pages share a section order. Marcus assigns an unused
permutation and records it. City and community pages draw from separate module pools.

### 3. NAP Registry — `generator/registry/nap.json`

Single source of truth for name, phone, email, hours, and service area. Every page renders
from this. Inconsistent NAP across pages actively suppresses local pack rankings.

## PRICING — THE FORMULA, EXPLICITLY

v1 multiplied home square footage by a rate and produced impossible numbers.

- **`typical_home_sqft`** = interior living area. Used for market context **only**. Never for pricing.
- **`typical_paintable_sqft`** = actual surface being coated (walls, fascia, trim, eaves).
  For two-story stucco this runs roughly 0.85–1.1× home sqft.
- **`exterior_rate_per_paintable_sqft`** = VIP's rate against *paintable* surface.
- **`typical_project_low/high`** = from **real VIP job data** for that city tier. Never computed.
  If no job data exists, set both to `null` and add to `gaps[]`.

### The honesty rule

`market.market_rate_range` is what the market charges. VIP's rate is usually above it — that
is correct for a luxury positioning, but the copy must never present VIP's rate as the market
average. Write it as *"VIP's Irvine exterior work starts at $X"*, never *"Irvine averages $X."*
The first is a defensible claim about your own pricing. The second is contradicted by public data.

## VALIDATION GATE

Run before Marcus notifies Seraphina:

```
□ All required fields present and non-empty for this page_type
□ meta.sources has a URL for every scraped data category
□ streets array has 2+ entries, each verifiable on Google Maps
□ palette.colors has exactly 4 roles: main_body, trim, gable, front_door
□ faqs has 6+ entries, each answer 2-4 sentences
□ meta_title ≤ 60 characters
□ meta_desc 150-160 characters
□ h1 contains the city name (and community name on community pages)
□ answer_capsule is 60-110 words, leads with who/where/what, ends with the phone number
□ viz_intro is 60-110 words and shares no sentence with any other brief
□ layout.module_order is unused in module-orders.json
□ story.is_real_client === true ONLY if the story exists in client-stories.json and is unused
□ typical_project_low/high came from real job data, or are null and listed in gaps[]
□ cost_answer_sentence does NOT claim VIP's rate is the market average
□ No occurrence of "AI" anywhere in customer-facing strings
□ No occurrence of "free" in customer-facing strings — use "complimentary"
□ Phone (909) 312-5400 and Contact@VIPHomePainting.com match nap.json exactly
```

Fail any check → write to `gaps[]`, lower `confidence`, hand off anyway with the flag.

## HOW SERAPHINA CONSUMES IT

```
1.  Read generator/briefs/{slug}.json
2.  Check meta.confidence — if not "high", continue but surface gaps in the report
3.  Read identity.page_type → city template or community template
4.  Read layout.module_order → section sequence; hero_variant → youtube or static
5.  Append the brief as an object in communities.json (community) or cities.json (city)
6.  Run: node generator/generate.js
7.  Generator validates: unique module order, no "free", NAP match, schema completeness
8.  Run the interlink reconciliation pass (below)
9.  Verify the built page: JSON-LD parses, no broken assets, nav anchors resolve
10. Commit, push. GitHub Pages deploys in ~60s.
11. Report published URL + gaps list
```

**Seraphina never writes HTML.** She writes structured data and runs the generator. This is what
keeps every page on the design system and makes a site-wide change a one-line edit.

## INTERLINK RECONCILIATION (runs after every publish)

Linking is a graph, not a per-page field. After any page publishes, rebuild all internal links
from the `identity` tree:

1. **Up:** every community page links to its `parent_url` (city) and the region page.
2. **Down:** every city page links to all its `child_urls` in the Communities module.
3. **Sideways:** every community page links to its siblings in the footer.
4. **Region:** the OC page links to every city page.
5. **Breadcrumbs:** regenerate `BreadcrumbList` schema so no crumb points at a 404.
6. **Sitemap:** rebuild `sitemap.xml` with every published URL.

> This step is why the six live community pages currently have a breadcrumb pointing at
> `/irvine/`, which 404s until the Irvine city brief ships.

### Research tool assignment

- **Semrush** — what to target. Volume, difficulty, organic competitor gaps.
  ⚠️ Hyperlocal community terms will report **zero volume**. That is a measurement floor,
  not an absence of demand. Never kill a community page on Semrush data alone.
- **Apify Google Maps** — who you're beating. Competitor GBP categories, review counts, and
  **review text**. Competitor complaints become your problem/solution content.
- **Apify social** — how people actually phrase it. Feeds FAQs, the answer capsule, and the
  Shorts scripts. Highest-value input for AI search, which doesn't rank on keyword volume.
